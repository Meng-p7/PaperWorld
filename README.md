# PaperWorld

把一篇论文，变成可以走进去的科研故事。

PaperWorld 是一个 AI 驱动的数字科研展览平台。上传 PDF 后，它在本机解析原文，把论文组织成四幕故事——为什么研究、怎么做、效果如何、价值与局限——并保留一份可逐字追溯的完整资料。每条重要结论都能回到论文原页核对。

**在线演示**：[meng-p7.github.io/PaperWorld](https://meng-p7.github.io/PaperWorld/)

首页会先带人靠近一座空间站：深空、环形居住舱、太阳翼与对接舱门，然后进入四幕故事。演示站点是纯静态页面；AI Core 后端需要另行启动。

## 核心体验

**四幕是唯一主线。** 首页首展、空间站的四个舱门、上传后的阅读入口、展览库入口，都进入同一份四幕故事。原来的七个编号展区不再占据普通读者的主路径，只在「完整资料」中按四个主题折叠出现：问题、解法、结果、价值与局限，参考文献放在文末。

**阅读优先，空间服务于阅读。** 空间站负责提供进入论文的空间感；正文仍是高质量 2D 排版。主线每幕最多一张核心图、一段短讲解、一个关键数字与少量证据；技术细节、完整数据与全部原文收进每幕的展开层。正常阅读约 2 分钟。

**空间站有真实的建筑体积。** 首页外景由本地 three.js 程序化搭建，包含环形舱、模块舱板、舷窗、中央脊柱、对接通道、舱门、太阳翼与散热板。空间站内部保持第一人称视角，拖动转头、对准舱门点击进入。桌面和手机共用同一主体，移动端降低渲染分辨率与阴影；低性能设备自动降档，并始终可以跳过动画。

**AI 负责理解与策展，不做聊天问答。** 接入 AI Core 后，模型分析论文、规划四幕、写讲解并挑选原文；结果写入展馆蓝图，之后浏览不再调用模型。模型配置只有 AI Core 一个入口，浏览器不接触 API Key。

## 使用流程

1. 打开首页，进入空间站选择一幕，或直接阅读首展。
2. 想看自己的论文，进入「上传论文」；PDF 在浏览器本地解析。
3. 需要模型参与时，先到「AI Core」启动并连接你的后端，再回上传页生成。
4. 生成完成后进入四幕故事；需要完整证据与原文页图时，再打开「完整资料」。

示范展 ALOHA / ACT 含 81 条逐字核对的原文证据、11 幅论文原图与 5 台互动装置。自动生成的展览沿用同一套蓝图格式与渲染器。

## 技术架构

| 层 | 实现 |
| --- | --- |
| 前端 | 纯静态站点，原生 ES Modules，无构建步骤、无框架、无 CDN |
| 首页空间站 | three.js（本地 vendored）程序化外景 + 镜头推进；动态画质降档 |
| 空间站内部 | three.js 电影级 PBR 环形大厅，舱门来自四幕故事；可降级到旧 WebGL 大厅或四幕列表 |
| 阅读层 | `story.html` 四幕故事；`hall.html` 完整资料，按四个主题折叠 |
| PDF | 本地 pdf.js 解析文字层、渲染原页并高亮引文 |
| 数据 | `paperworld.blueprint/v1`：meta / evidence / halls / blocks，前后版本兼容 |
| AI Core | `server/` 独立 Node 后端，代理模型调用、AES-256-GCM 加密保存密钥、异步策展任务 |
| 持久化 | IndexedDB 保存 PDF，localStorage 保存展览蓝图与索引 |

更细的模块说明、故事模型、存档映射与性能策略见 [docs/TECHNICAL.md](docs/TECHNICAL.md)。

## 隐私与准确性

PDF 文件与生成的展览只存在当前浏览器的 IndexedDB / localStorage，PDF 不上传服务器。若启用 AI Core，只会把已抽取的原文语句发给**你自己的后端**做策展；模型服务收到的内容也由你的后端转发，浏览器不直接持有 API Key。

自动展的正文只放 PDF 文本层的逐字字符串，不改写、不翻译、不补因果。编辑写的过渡句标为「策展语 · 非原文」，模型写的标为「AI 策展语 · 非原文」。模型不能新增证据：引文必须存在于证据表，讲解里出现新数值即丢弃。重要结论带页码，可打开原页并高亮。没有的数据不画。

## 本地运行

前端只需要一个静态服务器：

```bash
python -m http.server 8000
```

打开 `http://localhost:8000`。不要直接用 `file://` 打开，pdf.js 需要 HTTP 才能加载论文与 worker。

需要 AI 策展时，再启动独立后端（零 npm 依赖）：

```bash
PW_TOKEN=你的访问令牌 PW_SECRET=你的主密钥 node server/index.js
```

默认端口 8080，同时托管静态前端，因此本地也可以直接打开 `http://localhost:8080`。配置方式与接口说明见 [server/README.md](server/README.md)。

## 构建与开发

`assets/data/aloha.json` 由脚本生成并逐字校验：

```bash
python tools/build_blueprint.py
```

它会把 81 条引文与 `tools/pages.json` 中的 PDF 文本做去空白归一后比对；任何一条对不上，构建直接失败、不产出展览。`tools/` 下的抽取脚本依赖 PyMuPDF（`pip install pymupdf`）。

仓库根目录即站点根目录，`.nojekyll` 让 GitHub Pages 直接按静态文件发布。改完推送到 `main`，Pages 会自动重建。

## 已知边界

扫描版 PDF 没有文字层时无法解析，本版不含 OCR。双栏、脚注、跨栏表格与公式的阅读顺序可能还原错；作者署名靠版面启发式。自动展的插图由原 PDF 页面本地渲染，清晰度有限。原页高亮遇到跨栏断字可能定位不到，界面会明确提示。

六维度分析是启发式信号匹配，不是语义理解模型；措辞非常规的论文可能归类偏差。接入 AI Core 后由模型理解，但叙事质量取决于你接入的模型，服务端只负责校验与降级。

首页与空间站是程序化几何，不是精细建模资产；低性能设备会降低分辨率、关闭阴影，仍可能掉帧。展览与 PDF 存在当前浏览器，换设备或清除站点数据后不同步。
