# PaperWorld

把一篇论文，变成可以走进去的科研故事。

PaperWorld 是一个 AI 驱动的数字科研展览平台。上传 PDF 后，它在本机解析原文，把论文组织成四幕故事——为什么研究、怎么做、效果如何、价值与局限——并保留一份可逐字追溯的完整资料。每条重要结论都能回到论文原页核对。

**在线演示**：[meng-p7.github.io/PaperWorld](https://meng-p7.github.io/PaperWorld/)

首页会先带人靠近一座空间站：深空、环形居住舱、太阳翼与对接舱门，然后进入四幕故事。演示站点是纯静态页面；AI Core 后端需要另行启动。

## 核心体验

**四幕是唯一主线。** 首页首展、空间站的四个舱门、上传后的阅读入口、展览库入口，都进入同一份四幕故事。原来的七个编号展区不再占据普通读者的主路径，只在「完整资料」中按四个主题折叠出现：问题、解法、结果、价值与局限，参考文献放在文末。

**阅读优先，空间服务于阅读。** 空间站负责提供进入论文的空间感；正文仍是高质量 2D 排版。主线每幕最多一张核心图、一段短讲解、一个关键数字与少量证据；技术细节、完整数据与全部原文收进每幕的展开层。正常阅读约 2 分钟。

**空间站有真实的建筑体积。** 首页外景由本地 three.js 程序化搭建：环形居住舱、24 个分段舱体、径向桁架、中央脊柱、对接导向瓣与对开舱门、太阳翼、散热板、天线和外部货舱。材质使用程序化面板贴图、PBR 金属反射与柔和阴影，镜头从远景侧向接近舱门。空间站内部保持第一人称视角，中央展舱改为与阅读相关的「论文档案核心」，拖动转头、对准舱门点击进入。桌面和手机共用同一主体，竖屏单独构图；低性能设备与软件 WebGL 自动降档，并始终可以跳过动画。

**AI 负责理解与策展，不做聊天问答。** 接入 AI Core 后，模型先判断论文类型（机器人、算法、机械、材料、理论、综述、评测或通用实验），再按该类型的叙事重点组织四幕、写讲解并挑选原文；缺失的幕不会被强行填满。结果写入展馆蓝图，之后浏览不再调用模型。模型配置只有 AI Core 一个入口，浏览器不接触 API Key。

## 使用流程

1. 打开首页，进入空间站选择一幕，或直接阅读首展。
2. 想看自己的论文，进入「上传论文」；PDF 在浏览器本地解析。
3. 需要模型参与时，到「AI Core」填入自己的 API Key 即可——后端地址由页面自动确认，你不需要填。
4. 生成完成后进入四幕故事；需要完整证据与原文页图时，再打开「完整资料」。

AI Core 失败不会丢弃已解析的论文与本地四幕：修好后端后，可在结果区点「重试 AI 策展」，只重跑策展，不重新上传。

示范展 ALOHA / ACT 含 81 条逐字核对的原文证据、11 幅论文原图与 5 台互动装置。自动生成的展览沿用同一套蓝图格式与渲染器。

## 技术架构

| 层 | 实现 |
| --- | --- |
| 前端 | 纯静态站点，原生 ES Modules，无构建步骤、无框架、无 CDN |
| 首页空间站 | three.js（本地 vendored）程序化外景 + 镜头推进；动态画质降档 |
| 空间站内部 | three.js 电影级 PBR 环形大厅，舱门来自四幕故事；可降级到旧 WebGL 大厅或四幕列表 |
| 阅读层 | `story.html` 四幕故事；`hall.html` 完整资料，按四个主题折叠 |
| PDF | 本地 pdf.js 解析文字层、渲染原页并高亮引文 |
| 数据 | `paperworld.blueprint/v1`：meta / evidence / halls / blocks，前后版本兼容 |
| AI Core | `server/` 独立 Node 后端，代理模型调用、AES-256-GCM 加密保存密钥、异步策展任务 |
| 后端地址 | 由 js/core/endpoint.js 自动解析：显式声明 → 同源 → 已记住 → 本机 8080；界面上不出现“请填地址” |
| 持久化 | IndexedDB 保存 PDF 与蓝图，localStorage 保存小蓝图与索引；容量满时自动把旧蓝图迁到 IndexedDB，不删数据 |

更细的模块说明、故事模型、存档映射与性能策略见 [docs/TECHNICAL.md](docs/TECHNICAL.md)。

## 隐私与准确性

PDF 文件与生成的展览只存在当前浏览器的 IndexedDB / localStorage，PDF 不上传服务器。若启用 AI Core，只会把已抽取的原文语句发给**你自己的后端**做策展；模型服务收到的内容也由你的后端转发，浏览器不直接持有 API Key。

自动展的正文只放 PDF 文本层的逐字字符串，不改写、不翻译、不补因果。编辑写的过渡句标为「策展语 · 非原文」，模型写的标为「AI 策展语 · 非原文」。模型不能新增证据：每一幕的引文必须来自对应维度；讲解里出现数字时，会先补入包含该数字的原文证据，找不到就隐藏该数字或拒绝整幕；仍不合规会触发一次只含允许引文的修正轮。重要结论带页码，可打开原页并高亮。没有的数据不画。

## 本地运行

**推荐路径（含 AI 策展）**：一条命令，前端与后端一起跑起来，零 npm 依赖。

```bash
# Windows：双击 start-backend.bat（会自动打开浏览器）
# macOS / Linux：
node server/index.js
```

然后访问 `http://localhost:8080`。这个地址本身就是完整站点：首页、上传、AI Core 都在里面。
需要开鉴权时再带环境变量：`PW_TOKEN=你的令牌 PW_SECRET=你的主密钥 node server/index.js`。

**只预览前端**（不使用模型）：

```bash
python -m http.server 8000
```

打开 `http://localhost:8000`。这条路径没有后端，AI Core 会显示「启动本机服务」的引导；上传与四幕仍可用本地分析生成。
不要直接用 `file://` 打开，pdf.js 与 ES 模块都需要 HTTP。

### 后端地址是怎么确定的

界面上不会出现「请填写后端地址」。`js/core/endpoint.js` 按这个顺序自动确认：

1. 代码里显式声明的地址（部署到自己的域名时改这一行，终端用户看不到）；
2. 你上次连接成功记住的地址；
3. 当前站点同源——用 `start-backend.bat` 打开时就是这种情况，零配置；
4. 本机 `http://localhost:8080` / `http://127.0.0.1:8080`。

只有两种情况才需要展开 AI Core 里的「高级」：后端部署在别的域名，或后端设置了 `PW_TOKEN`。

## 构建与开发

`assets/data/aloha.json` 由脚本生成并逐字校验：

```bash
python tools/build_blueprint.py
```

它会把 81 条引文与 `tools/pages.json` 中的 PDF 文本做去空白归一后比对；任何一条对不上，构建直接失败、不产出展览。`tools/` 下的抽取脚本依赖 PyMuPDF（`pip install pymupdf`）。

仓库根目录即站点根目录，`.nojekyll` 让 GitHub Pages 直接按静态文件发布。改完推送到 `main`，Pages 会自动重建。

## 已知边界

扫描版 PDF 没有文字层时无法解析，本版不含 OCR。双栏、脚注、跨栏表格与公式的阅读顺序可能还原错；作者署名靠版面启发式。自动展的插图由原 PDF 页面本地渲染，清晰度有限。原页高亮遇到跨栏断字可能定位不到，界面会明确提示。

论文类型判断与六维度归类是启发式信号匹配，不是语义理解模型；措辞非常规的论文可能归类偏差。接入 AI Core 后由模型理解，但叙事质量取决于你接入的模型，服务端负责事实、引文与数值校验，并在缺失时降级或补证。

首页与空间站全部是程序化几何，没有加载外部 GLB；`assets/exhibits/manifest.json` 为空，`assets.js` 只有在存在带明确许可的资产时才会加载。当前不假装使用模型资产。低性能设备与软件 WebGL 会降低分辨率、关闭阴影、简化材质；极低端仍可能掉帧。展览与 PDF 存在当前浏览器，换设备或清除站点数据后不同步。
