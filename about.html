关于 PaperWorld

先让人看懂，
再让细节可查

PaperWorld 不是论文问答机器人，也不是一份更长的论文分析。它把论文重新组织成四幕短故事， 让人在几分钟内明白问题、方法、结果与边界；需要深入时，再展开技术细节、全部原文与证据页码。

四幕是唯一主线

全站默认进入同一份四幕故事：为什么研究、怎么做、效果如何、价值与局限。类型不同，四幕的标题与讲解重点也不同：机器人论文看硬件与真实任务，算法论文看改动与基准，材料/机械论文看结构、工艺与实测，理论论文看假设与适用范围，综述看框架、分歧与空白。空间站的四个舱门、 首页的首展入口、上传后的阅读入口、展览库入口，都指向这篇故事。

原来的七个编号展区不再占据普通读者的主路径，只在「完整资料」里按四个主题折叠出现。 那里保留全部原始分厅、互动装置、原文页图与参考文献；它是档案，不是默认阅读。

空间与阅读各做各的事

首页用 three.js 程序化搭建空间站外景：环形居住舱、分段舱体、径向桁架、中央脊柱、对接导向瓣与舱门、太阳翼、散热板和天线。材质、环境反射与阴影都来自本地程序化资源；当前没有引入外部 GLB。 镜头从远景接近对接舱门，再进入空间站。桌面与手机保留同一主体，移动端降低分辨率与阴影；低性能设备自动降档， 也可以直接跳过动画。

空间站内部仍采用第一人称视角，四个舱门来自故事的四幕。正文阅读保持高质量 2D，不为 3D 效果牺牲排版、 可读性与操作效率。

AI 只负责理解与策展

模型在生成时分析研究背景、核心问题、创新点、技术路线、实验过程与结果，规划四幕、撰写讲解、挑选原文。 展馆写入蓝图后，正常浏览不再调用模型，也不持续消耗 Token。

模型会先判断论文类型，再组织该类型适合的四幕叙事。每一幕引文必须来自对应维度；讲解里的数字必须能在本幕原文中找到，找不到会补入对应证据或隐藏该数字；仍有缺失时会触发一次只使用允许引文的修正轮。

模型配置只有 AI Core 一个入口。浏览器不直接保存 API Key； 密钥由你的后端用 AES-256-GCM 加密保存，接口与日志都不回显。未连接后端时自动使用本地类型分析与六维度分析， 展馆仍可生成。

准确性边界

原文就是原文：自动展的正文只放 PDF 文本层的逐字字符串，不改写、不翻译、不补因果。编辑写的过渡句明确标为 「策展语 · 非原文」，模型写的标为「AI 策展语 · 非原文」。模型不能新增证据，引文必须回查证据表；讲解中的数字若不在本幕引文中，会先补入包含该数字的原文证据，仍找不到则隐藏或拒绝该幕。

重要结论挂页码，可打开 PDF 原页并高亮引文。页面只画论文报告过的数字，不插值、不推测。

仍然做不到的

扫描版 PDF 没有文字层时无法解析，本版不含 OCR；双栏、脚注、跨栏表格与公式的阅读顺序可能还原错； 六维度分类是启发式信号匹配，措辞非常规的论文可能归类偏差。原页高亮遇到跨栏断字时可能定位不到， 界面会明确提示。

空间站是程序化几何，不是精细建模的资产；低性能设备可能掉帧。展览与 PDF 存在当前浏览器的 IndexedDB / localStorage，换设备或清除站点数据后不会同步。
