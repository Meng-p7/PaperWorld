2.0 把展馆放进了深空：镜头穿过星云与曲速隧道对接空间站，再进入一间间展区。 但越像电影，越要守住一件事——别在转述里悄悄改掉作者的意思。 能直接引用的就一个字不改地引用，需要过渡的地方就明说这是编辑写的，模型写的更要标出来。

01 / SPATIAL EXPERIENCE

三层空间，各司其职

COSMOS 深空
宇宙入口
WebGL 星云 shader、3D 透视粒子、星球与全息空间站。点击或滚动推进镜头，巡航 → 曲速 → 对接；随时可跳过动画。
STATION 空间站
展区中枢
CSS 3D 透视走廊里排布真实展区节点，编号、名称、证据数都来自蓝图。点节点镜头自动移动并进入对应展区。
HALL 展馆
高质量 2D 阅读
全息导航条 + 短转场负责空间感；正文排版、证据抽屉、原页高亮、互动装置保持 2D，不为特效牺牲可读性。
02 / CURATION PIPELINE

AI 的职责是理解论文、生成展馆

STEP 01
取文字层
pdf.js 逐页读回文本项与坐标，按 y 归行、按 x 判断单/双栏，拼回可读顺序。
STEP 02
认结构
标题、作者、摘要、章节、Fig./Table 图注、数值线索、参考文献。
STEP 03
六维度分析
按原文措辞信号与版面位置，把句子归入研究背景 / 核心问题 / 创新点 / 技术路线 / 实验过程 / 结果与结论。
STEP 04
动态规划展区
只建有原文依据的维度；按维度选随机展签、章节地图或数值扫描；展品是逐字原句 + 页码锚。
STEP 05
讲解（可选模型）
可接入 OpenAI 兼容模型写策展语、挑展品；返回逐条校验，不合规即降级。生成一次后写进蓝图，逛展不再调用。
STEP 06
进入空间
蓝图交给同一套渲染器；空间站读取 halls 生成展区节点，镜头对接后落到 2D 展馆。

内置示范展走另一条更严格的路：81 条引文由构建脚本逐条与 arXiv:2304.13705v1 的 PDF 文本做去空白归一后比对，任何一条对不上，构建直接失败、不产出展览。

03 / ACCURACY CONTRACT

五条不会让的规矩

原文就是原文
自动展的正文只放从 PDF 文本层拼回来的逐字字符串。不改写、不翻译、不概括、不补因果。
策展语显式标注
编辑写的过渡句用「策展语 · 非原文」单独成块；模型生成的讲解标成「AI 策展语 · 模型生成 · 非原文」，永远不混进原文段落。
模型不能新增事实
模型只输出展区讲解与展品挑选；引文 id 必须存在于证据表，讲解里出现新百分比即丢弃该条，失败自动降级到本地分析。
重要结论必须可回到原页
每个原文块都挂页码标记，点开给出原句与页码，再点一次直接渲染那一页 PDF 并尝试高亮。
没有的数据不画
展区数量由实际检出的原文条数决定；数值扫描只画原文出现过的数字，不插值；消融图只摆论文报告过的锚点。
04 / ARCHITECTURE

技术架构

层实现为什么这样选
运行时纯静态站点，原生 ES Modules，无构建步骤、无框架、无 CDN 依赖可直接托管在 GitHub Pages；离线也能打开；长期可维护。
空间站原生 WebGL 第一人称环形大厅（走廊/地板/穹顶/支柱/舱门/灯带/雾）+ DOM 铭牌投影；无 WebGL 时降级 CSS 3D 走廊要的是真实建筑结构与空间层次，不是悬浮卡片；拖动转头带惯性，对准舱门推门进入。
科研故事story.html 五幕结构 + 通俗/技术/原文三层内容让没读过论文的人几分钟看懂；结论仍由原文承担，可回原页高亮。
AI Coreserver/ 独立后端：AES-256-GCM 加密存 Key、模型调用代理、异步策展任务队列浏览器不接触 API Key；密钥、限速、超时、异常都收敛在服务端。
宇宙层WebGL fragment shader（星云/星球/曲速光条）+ Canvas2D 透视粒子 + CSS 3D 空间站走廊只在入口与转场用特效，正文层零 WebGL；WebGL 不可用自动降级到 Canvas2D 静态星图。
镜头独立的 camera.js 把滚动/点击映射为 z 与 warp 数值，阶段为巡航 / 曲速 / 对接动画与渲染解耦；reduced-motion 直接跳过；页面隐藏时停帧；移动端减少粒子与 DPR。
策展引擎analyze.js 六维度分类 → curate.js 动态规划展区 → llm.js 可选模型适配展区结构由论文内容决定，不是模板；模型输出必须回查证据表才能落地。
PDF本地打包的 pdf.js，逐页取文本项并渲染原页溯源要拿到「那一页」和「那几个字的位置」，只能自己解析 PDF。
数据paperworld.blueprint/v1 JSON：meta / evidence / halls / blocks1.0 的蓝图格式原样保留，示范展、自动展、空间站共用一套渲染器。
持久化IndexedDB 存 PDF Blob，localStorage 存展览蓝图与索引刷新后仍能重开展览并做原页高亮；文件不上传服务器。
校验构建期逐字比对；运行期证据引用完整性检查；浏览器双端渲染与性能体检把「不编」做成可执行的检查，而不是一句口号。
05 / DEMO CASE

首展为什么选 ALOHA / ACT

《Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware》同时具备三样东西： 看得见的硬件、能动手演示的算法、成体系的真实实验数据。它天然适合拆成「标本柜—机械厅—实验台」三段。 论文用两万美元的低成本双臂装置，把开杯盖、装电池、穿扎带这类毫米级精细操作做到了 80–90% 成功率， 也明确写下了两个学不会的任务。一个愿意把失败摆出来的研究对象，最适合做第一座诚实的展馆。

06 / KNOWN LIMITS

现在还做不到的

如实列出，免得你踩坑

  • 扫描版 PDF 没有文字层，解析会直接报错；本版本不含 OCR。
  • 双栏、脚注、跨栏表格与数学公式的阅读顺序可能被还原错，复杂的 LaTeX 论文需要人工复核。
  • 六维度归类是启发式信号匹配，不是语义理解模型；遇到措辞非常规的论文可能归类偏差或漏检，漏检时界面会写「未检出」。
  • 外部模型默认关闭；填写端点后仍可能因为浏览器跨域限制而被拒绝，此时会自动降级到本地分析，并在策展解读里说明原因。
  • AI Core 后端需要你自己起服务（node server/index.js）或部署到主机；GitHub Pages 只托管静态前端。后端不可用时自动降级到本地六维度分析，展馆仍能生成。
  • 模型策展的产出是「故事五幕 + 展区讲解 + 挑展品」，不是写论文分析报告；它的事实必须能回查到证据表，做不到就丢弃该条。因此叙事质量取决于你接的模型，也可能比通用聊天式 AI 朴素。
  • 第一人称空间站是原生 WebGL 程序化几何（环形大厅、舱门、灯带、雾），不是精细建模的 3D 场景；低性能设备可能掉帧，可用「跳过动画」直接进馆。
  • 生成式模型只写策展语与挑展品，不做跨段推理、不写结论，因此叙事仍比通用聊天式 AI 朴素。
  • WebGL 不可用时星云会降级为静态 Canvas 星图；低性能设备会减少粒子数与 DPR，镜头动画可通过「跳过动画」完全略过。
  • 原页高亮依赖引文在 PDF 文本项里能连续匹配；跨栏或断字严重时可能定位不到，此时会提示「未定位到引文」。
  • 展览存在浏览器本机，换设备、换浏览器或清除站点数据后不会同步；上传的 PDF 也只在本机。
